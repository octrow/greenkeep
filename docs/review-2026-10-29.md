## 3. Находки (проблемы), по приоритету

### 3.1 HIGH — лимит Claude «сжигает» весь прогон

26 окт в 00:22 `UsageLimitError` прилетел на `ollama-rename-files`, и дальше **8 репо подряд** упали с тем же исключением (`run failed` × 8 в логе, `8 problems` в дайджесте). `run.py:_not_the_change` правильно не засчитывает попытку, но пробрасывает исключение, а `cli.py:_run_all` ловит его как обычную ошибку репо и идёт к следующему: снова клон, `uv sync`, полный тестовый прогон, вызов Claude, тот же отказ. Потом `record_run()` помечает день выполненным, и следующий часовой запуск ничего не делает, хотя лимит к утру сбросился.

**Что сделать:** при `UsageLimitError` прекращать LLM-работу до конца прогона (детерминированные vuln/ruff/readiness можно продолжить) и **не вызывать `record_run()`**, тогда часовой таймер сам повторит прогон позже.

### 3.2 HIGH — сбой сети засчитывает день

24 окт ночью 4 репо (`market-sources`, `buy-smarter`, `jobs`, `finance-insights`, все из **focus**) упали на `Could not resolve host: github.com`: ноутбук ещё не поднял сеть. Прогон всё равно был помечен выполненным.

**Что сделать:** тот же механизм, что в 3.1: если ошибка транзитная (DNS/сеть, лимит), день не считается выполненным, следующий час пробует снова. Минимальный вариант: флаг `digest.transient`, при нём пропускать `record_run()`.

### 3.3 MEDIUM — `==`-пины делают bump невозможным

Все 5 outdated-находок в `jobs` (lxml, nicegui, python-dotenv, python-jobspy, typer) запаркованы с одной ошибкой:
`Because jobhunt depends on typer==0.27.1 and typer==0.27.3 … unsatisfiable`. В `jobs/pipeline/pyproject.toml` зависимости зафиксированы точно, а `uv lock --upgrade-package` не может выйти за пин. Побочный эффект: 2 parked подряд → focus-репо `jobs` уходит в cool-down (снимался 26 и 28 окт), и его остальная работа тоже откладывается.

Хуже всего то, что **уязвимость** в пакете с `==`-пином запаркуется так же, и это security.

**Что сделать:** для `==`-пина переписывать пин в `pyproject.toml` (детерминированно, это одна строка), потом `uv lock`. Минимум — не создавать outdated-находку для точного пина.

### 3.4 MEDIUM — отпечаток уязвимости = полный список CVE

`fp = vuln:pillow:CVE-…+CVE-…+…`. Когда для того же пакета публикуется ещё одна CVE, отпечаток меняется, и появляется новая находка. В `repo-scout` pillow починен в #19, но issues **#13 и #14** (тот же pillow, старые наборы CVE) так и висят открытыми с `needs-human`.

**Что сделать:** отпечаток по пакету (`vuln:pillow`), либо при merge фикса пакета закрывать открытые issues этого же пакета.

### 3.5 MEDIUM — characterization-тесты: дорого и мало толку

~3 merged против 20 parked. `cc-bench` — 8 parked из 8 попыток. Повторяющиеся причины (из отказов ревьюера):

- тесты генерируются **для тестовой обвязки** (`chat-watch: bot/tests_e2e/helpers.py`, `make_session.py`);
- импорт пакета из optional extra (`telethon` только в `e2e`) → обычный suite упадёт;
- не тот стиль: в репо plain-assert скрипты с `if __name__ == "__main__"` или русские docstrings во всех ~49 тестах;
- дублирование уже существующих тестов в соседнем файле;
- line budget превышен на 5–10 строк (160 при лимите 153), 9 отказов за неделю.

**Что сделать (по возрастанию затрат):**
1. Не создавать находки для модулей под `tests*/`, `test_*`, `conftest.py`.
2. Line budget: допуск +10%, либо сообщать патчеру точное число строк в feedback (сейчас ретрай всё равно перелезает).
3. Не делать находки для модулей, импортирующих пакеты, которых нет в `dev`-зависимостях (по аналогии с уже существующим правилом для psycopg/redis).
4. Если в репо 3+ parked тестовых находки, перестать генерировать тесты в нём (а не только cool-down на 7 дней).

## 4. Откровения

1. **Ревьюер — самая ценная часть пайплайна.** Gate проверяет, что тесты зелёные и строки покрыты, а ревьюер ловит то, чего gate не видит: тавтологичные assert'ы, задублированный assert после «фикса» SIM201, сломанное поведение при двойном cancel в bug-fix'е nicegui-kit, ложную readiness-находку. Без него на неделе 2 до merge дошли бы 11 изменений, которые прошли gate, но были плохими.
2. **Bug hunt работает дёшево.** Hunter+Skeptic стоят около $0.12 за модуль и нашли 3 реальных бага. Referee в виде «тест красный до фикса» (ADR-0002) себя оправдал.
3. **Бюджет — главный ограничитель, а не качество.** Каждый день `budget left today: 0` и `9 waiting for budget`. При 19 репо и 3 merge/день до каждого репо очередь доходит раз в ~6 дней. Если цель — «живые» репо и зелёные квадраты, бюджет 3 слишком мал. Если цель — не заваливать себя PR, всё правильно.
4. **Dependabot и greenkeep делают одну работу.** 4 PR Dependabot закрыты, потому что greenkeep смержил тот же bump раньше (`buy-smarter#21/#22`, `repo-scout#15`, `tiktok-lazy-follower#5`). При этом **34 PR Dependabot висят открытыми** (в основном actions-группы), их никто не мержит.
5. **Растёт бэклог `needs-human`: 31 открытый issue,** 2/3 из них — запаркованные тесты. Дайджест сообщает о них один раз, дальше они просто копятся.
6. **Стоимость ничтожна:** 180 вызовов Claude за 2 недели ≈ $20 API-эквивалента, фактически в рамках подписки. Узкое место — время прогона (20–40 мин/ночь, в основном `uv sync` и тестовые suite) и лимиты подписки (3.1), но не деньги.

### 7.4 Разделение работы с Dependabot

Dependabot настроен почти во всех tended репо (uv/pip + github-actions, кроме LaptopLoot), и он бесплатный. Что он умеет и чего нет:

| | Dependabot | greenkeep |
|---|---|---|
| Найти устаревшую зависимость, открыть PR | да | да (дубль) |
| Security-bump по advisory | да (security updates) | да, и мержит сам |
| Обновить GitHub Actions | да | нет |
| **Смержить на зелёном** | нет (только auto-merge через workflow) | да |
| Проверить локальным suite, если CI не работает | нет | да |
| Lint, тесты, bug hunt, readiness, ревью | нет | да |

**Рекомендация:**
1. **Outdated** — отдать Dependabot: в репо, где `dependabot.yml` покрывает `uv`/`pip`, greenkeep не создаёт outdated-находок. Это сразу убирает дубли (buy-smarter#21/#22, repo-scout#15, tiktok#5) и проблему `==`-пинов в jobs (3.3): Dependabot сам правит пин в pyproject.
2. **Vuln** — оставить greenkeep: он мержит в тот же день, Dependabot только открывает PR.
3. **Новая роль greenkeep: мержить зелёные Dependabot PR** (patch/minor, без major) после своего локального gate. Токенов на это не нужно, а 34 висящих PR сойдут на нет. Особенно полезно, пока CI в приватных репо не работает.

**Сделано 29 окт:** пункт 1 — `deps.dependabot_updates_deps`, outdated-находок нет там, где `dependabot.yml` покрывает `uv`/`pip`. Пункт 3 — `dependabot.merge_safe`: после своих фиксов greenkeep тестирует до 3 PR Dependabot на репо за прогон, на голове PR (`--match-head-commit`), и мержит зелёные с тем же мажором. Actions-only PR мержатся только на зелёных checks, поэтому в приватных репо они ждут, пока вернутся минуты Actions.

### 7.5 Boost (сделано)

В конфиге `boost_until = <время с offset>` и `boost_budget` (по умолчанию 15). Пока boost активен, каждый часовой запуск таймера — полноценный прогон (`ran_today` игнорируется), бюджет = `boost_budget`. Заодно исправлен 3.1: на `UsageLimitError` прогон останавливается на этом репо и день не засчитывается, так что следующий часовой запуск повторяет. Claude-вызовы идут через логин Claude Code (`stripe_subscription`, org Cybernet AI), `ANTHROPIC_API_KEY` в окружении сервиса нет, то есть API не используется. Пока идёт boost, bug hunt работает во всех tended репо, не только с `hunt = true`.
